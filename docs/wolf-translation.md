# Wolf 实时字幕翻译（实验版）

当前实现的是 **运行中的游戏文本捕获 → 本地词典匹配 → 独立中文字幕窗口**。
它不是原版的游戏内替换绘制，不会让游戏的日文字体/菜单原位置变成中文。

## 直接使用

在这台电脑上双击根目录 `wolf-subtitles.cmd` 即可测试已提供的游戏。
也可以传入目录：

```powershell
.\wolf-subtitles.cmd "tests\testgame\JPN HENTAI RABBIT HOOD"
```

首次构建需要本机 MSVC x86 C++ 工具；Python 3.12+ 必须带 Tkinter，另需 Node.js 22+、Git。
构建脚本只下载固定提交的 MinHook 并构建本项目，不安装或升级系统工具。
默认读取游戏目录中的 `翻译文件.json`，也可手动指定词典：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-wolf-capture.ps1
python scripts/wolf-subtitles.py "游戏目录" --dictionary "本地词典.json"
```

词典支持 `{ "原文": "译文" }` 或 `[["原文", "译文"]]`。
不联网、不调用翻译 API；未命中的文本保留原文。词典中的部分错误翻译不会被自动修正。

## 当前支持范围

- **仅支持已验证 EXE 的 SHA-256**：
  `e0716a35323007c79e6033bc19c610a38e1d4ccc0dce47c6f79cf706853e5b76`。
- 即用户提供的 x86 Wolf 2.24 游戏 EXE。不是支持所有 2.24 游戏；换版本或修改 EXE 会拒绝启动。
- 捕获消息绘制函数读取的文本，不支持图片内文字、动画贴图文字等不可见于该函数的内容。
- 已在捕获边界按字节移除当前配置的绘制控制块，再以 CP932 解码为纯文本；
  译文通过独立 Unicode 窗口显示，不复刻游戏内颜色/坐标布局。
- 使用恢复出的 AC 自动机/换行重排实现匹配，不依赖 MV 游戏全局对象。
- 字幕是与游戏分离的置顶窗口，可以拖动；不是绑定游戏坐标或嵌入全屏画面的叠加层。
- 目前只验证启动/菜单阶段，完整剧情、读档、长期稳定性和 Steam Deck 尚未验证。

## 文件与进程边界

1. 校验原 EXE 散列，拒绝未知目标。
2. 将整个游戏复制到忽略的 `work/wolf-runs/独立目录/game`，不会在原目录安装 DLL。
3. 原生启动器新建游戏进程并用 kill-on-close Job Object 管理，不附加已有 PID。
4. 向该新进程加载本项目编译的捕获 DLL；MinHook 修改它的绘制函数入口，**会修改副本进程内的代码**，
   但不修改磁盘 EXE、游戏消息字符串、数据库或存档。
5. 捕获文本和本地译文只保存在本机 `work/`，不提交到 Git。
6. 关闭字幕窗口会结束本次游戏副本；如需保留游玩进度，请先在副本中保存。
   保存结果留在副本目录，不会自动同步到原游戏。

**独立副本不是操作系统安全沙箱。** 游戏仍以当前用户权限运行，原程序本身如包含其他行为，
本工具无法隔离。请只运行你信任并有权测试的游戏；无需管理员权限，也不应关闭安全软件。

每次运行会复制约 100 MiB 的样本游戏，副本保留供检查，不自动删除或合并。
捕获日志限 20 MiB；达到上限会提示捕获停止。词典限 32 MiB/100,000 条，
单条原文限 8,192 字节，翻译缓存限 512 条，捕获去重表限 2,048 条。
这些是本工具的资源限制，不是原软件或 Wolf 引擎的格式限制。

## 验证

```powershell
npm test
npm run test:wolf-state
python scripts/wolf-subtitles.py "tests/testgame/JPN HENTAI RABBIT HOOD" --smoke-seconds 15 --validation-report evidence/wolf_subtitles_validation.json
```

验证会打开游戏副本与字幕窗口，运行 15 秒后关闭。报告不包含游戏文本，
只有捕获/命中/显示计数、散列与未验证范围；完整捕获内容留在 `work/`。
原目录所有文件的大小、mtime 和 SHA-256 都会在测试前后比较。

`uiMatchedShown` 表示程序实际更新了可见 Tk 标签，不是 OCR/像素级渲染等价性证明。
没有词典命中、出现解码/工作进程错误或丢包的烟雾测试不会报告通过。

需要截图时添加 `--screenshot`（需 Pillow），截图只保存到本次运行的
`work/wolf-runs/.../subtitle-window.png`，不会上传游戏画面。
可用 `python scripts/verify-wolf-display.py "本次运行目录"` 校验界面时间记录、控制字节和图片文件；
该校验不代替人工查看截图。

## 方框与旧文本快速回放的修复

首版缺陷：内部格式控制字节未经解码就送到 Tk，导致方框；捕获缓存只在发出事件时更新，
使仍在绘制的旧文本每 3 秒重发，字幕又将多个结果依次显示。

现在在每次绘制时刷新 last-seen，持续可见文本不再周期性重发；
格式块在 CP932 解码前按字节消费，不能只用正则删除控制字符，否则坐标参数仍会泄漏。
后续只保留最新稳定文本，不存放待播放历史；每个输入带 generation，
已被新文本取代的翻译结果不能写回界面；相同可见字幕不重复绘制。

12 项 Python 回归覆盖持续重绘 30 秒、多个标签并行重绘、最新值替换、
过期结果拒绝、停止清理，以及二进制格式参数/编码边界。

## 逆向依据与实现差异

- 原 x86 DLL `100605d0.c` 选择 2.24 消息绘制分支。
- `100bc568.c` 的特征匹配及向前搜索函数序言，用于定位目标绘制函数。
- `100bcf90` 的反汇编与 `100bd12c.c` 表明签名为 this/fastcall 的容器指针、char 与三个 double，
  并处理两段旧式 28 字节字符串（数据偏移 4、长度 20、容量 24）。
- 在实际 Game.exe 中核对到绘制函数 RVA `0x94480`，经 REA 实际反编译核对 ECX 容器与 28 字节字符串。
  游戏自身的伪代码仅保留在本地 `work/wolf-draw-decompile.json`，不公开提交游戏代码。
- 原版还用自定义分配器、编码和临时字符串替换来完成就地中文绘制；该部分未恢复。
- 本实现只复用了已核对的捕获边界，字幕窗口和进程管理是新写的替代接入层。
- Frida 附加该旧 x86 进程失败，因此当前版本不依赖 Frida，也不把失败尝试算作验证通过。
